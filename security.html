Tori: Security and data handling

Version 20261028 · Octo Fintech Holdings LLC · This page is the reference for what Tori receives, how it moves, what it keeps, who else handles it, and how it is protected. The Privacy Policy and any signed data processing addendum point here for the specifics.

1. What Tori receives

Tori receives data when you sign in, when an agent session starts, and when a check runs, which happens when your coding agent finishes a task or when you run a Tori command yourself.

The check selects files by git status, so untracked work in progress in the same repository is included unless you exclude it. Paths you list in .tori/project.json under ignore (tori ignore add fixtures/, seeds/**, scratch) are never sent for checking, never appear in the file-path list, and never leave your machine; re-running tori init preserves the list.

Tori does not receive any other file, your application's runtime data, your customers' data, or credentials. It never reads the repository as a whole and runs no background process.

2. What Tori does with it

The files are checked against rules on Tori's servers. The checks are deterministic rules. No AI model or model provider is in the data path. The data is not used for any other purpose, not used for training, and not shared with or sold to anyone.

3. How the data moves

  1. Your agent finishes a task
  2. The Tori command-line tool runs on your machine and reads the code files git reports as modified or untracked, minus ignored paths
  3. It sends them over HTTPS (TLS) to Tori's API, hosted on Vercel
  4. The check runs in memory on Vercel; the files are not written to storage
  5. The results (findings and the signed record) are written to Tori's database, hosted on Neon

Processing and storage are in the United States (AWS us-west-2, Oregon).

Vercel runtime logs (request metadata, application messages) are retained for 1 day. Neon's restore window is 1 day, meaning deleted data can be recovered for up to 1 day after deletion and not after.

On request, or when the account is closed, findings, records and account details are deleted within 30 days.

6. Security

  • All traffic between your machine and Tori is encrypted with TLS
  • Data at rest in the database is encrypted by Neon
  • The key that signs the record is stored as a protected secret on Tori's servers and never leaves them. Any receipt can be verified on your own machine with no network connection and no Tori software; a changed record fails verification.
  • Production access is held by the founder, with MFA on both consoles and separate production credentials. That access reaches findings, the signed record and account details; it never reaches file contents or any end-user data, which Tori does not hold

7. Commitments

  • Breach notification: within 72 hours of Tori becoming aware of a security incident affecting your data
  • Deletion on request or termination: within 30 days
  • Notice before any new subprocessor: 30 days
  • Notice before granting production access to an additional operator: 30 days
